# v1.5.0 release evidence

2026-11-08. [中文](V1.5.0-RELEASE.md)

This release integrates development commit `e27bc6114a8866fe7fce51af8138bbc03d26aab1` onto release base `508b1fff58b8bd894c4c495e879dbb0ee5c8711a`. The base theme, motion wallpaper, SDDM, controller and distribution metadata use version 1.5.0.

## Changes and limits

- The selected Medical Green lock wallpaper shows the time and date in the upper-left corner; waking reveals the initial avatar and password field in the same column. Plasma authentication is retained.
- Logout, restart and shutdown prompts draw the bundled lock wallpaper at its original brightness over windows and panels, with the clock, countdown and controls on the left.
- SDDM footer keyboard focus uses opaque dark and light outlines, including the error layout.

With a custom lock wallpaper, all three confirmation prompts still show the bundled wallpaper. SDDM remains experimental, separate and disabled by default. Installation does not enable the SDDM service.

## Separate validation environments

The development records include 24 isolated offscreen Qt confirmation checks: 20 passed; four failed an old assertion requiring zero full-screen colored elements, which also counts the wallpaper container. Esc, Cancel and blank-click cancellation signals passed in all four sizes. These checks are not authentication evidence.

Historical VM checks at 3120×2080 and 175% measured eight SDDM focus images at or above 3:1 against adjacent wallpaper. The minimum between the two outlines was 12.9167:1; shutdown focus minima were 3.6157:1 and 3.5991:1. Six 29-second confirmation images over different backgrounds differed by at most 7 pixels with maximum channel difference 2; Cancel focus measured 3.2424:1. One VM blank click did not close the prompt within 10 seconds; protective Esc returned to the original session. That failure is retained.

Paired fresh VMs for the parent and development commits produced unmasked lock-error comparisons of 20 pixels / maximum channel difference 8 at +0.5 seconds and 13/8 at +1.5 seconds. At +3.0 seconds, different authentication timing caused 18,187/213; both VMs subsequently unlocked into their original sessions. This later failure is retained.

Candidate `c13e1aaf64759aeadff3c10c9ad489b78f50d74a` passed 115 Python tests, flake check and all three package builds. Its accepted VM comparisons were first-default 16/4, focused-default 16/4, error 32/7, shutdown focus 41/7 using an explicitly accepted same-condition pair, lock wake 6/3, and the 29-second confirmation 10/2. Comparisons retained the prescribed clock/countdown masks and limits of 100 pixels and maximum channel difference 8. The historical first-frame failure (1,788/207), old shutdown-focus-reference failures and caret-phase failures remain recorded. Final publication tests, builds and attachment verification are recorded separately in repository Actions and release assets.

## Maintainer-reported physical checks

The candidate was deployed using build then boot; after reboot, read-only checks confirmed the built system and 1.5.0 resources. Publication preparation changes documentation only, with runtime code identical to the deployed candidate.

On a single Wayland display at 3120×2080 and 175%, the maintainer reported normal transparent layout, wallpaper brightness, readable text, SDDM first-character input, wrong-password feedback followed by successful login, retained first-letter lock wake, immediate retry and unlock after an error, and suspend/resume/unlock. A single blank-area click cancelled the restart prompt: W8 gains a physical pass while its earlier VM failure remains.

These interactions are maintainer-reported, not automated UI or pixel checks. Successful startup and session state have separate read-only system checks. No physical screenshots or contrast measurements were collected; logs did not independently corroborate suspend timing. Full shutdown/logout workflows, multiple displays, TTY recovery and boot-menu rollback were not retested.

## Install and distribution

From the 1.5.0 source directory, run `nix build --no-write-lock-file path:.#kaltsit-theme`. Build and install `kaltsit-motion` and `kaltsit-sddm` separately; SDDM requires explicit enablement. Modules use the caller's `pkgs`. Restore an active old backup using its original version before upgrading. See [installation](../README.en.md), [recovery](UPGRADE-RECOVERY.en.md), [SDDM](SDDM.en.md) and [motion](MOTION.en.md).

The source archive is `kaltsit-medical-green-1.5.0.tar.gz`. Attribution, sources and licenses are listed in [CREDITS](../CREDITS.md) and [LICENSES](../LICENSES/). Video and optional OPPO font files are not distributed.
