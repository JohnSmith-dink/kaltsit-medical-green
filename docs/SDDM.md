# 登录界面（SDDM，实验性）

`kaltsit-sddm` 是独立的 Qt 6 静态登录主题，默认不启用。它不改变原桌面、锁屏、Home Manager、认证策略或日常恢复记录。仅使用仓库已有静帧，颜色在构建时从既有配色提取。
初版设计依据、锁定版本及回退边界见 [SDDM 设计](SDDM-DESIGN.md)。下述 v6 是未发布的界面修订，包版本仍为 1.3.0。

## v6 字体、视觉对齐与键盘操作

- 壁纸保持原图亮度和等比裁切；登录容器完全透明，没有面板底色、外框、阴影、模糊或整屏遮罩。使用已有色板。
- 若 Qt 能找到本地 `OPPO Sans 4.0`，使用该字体，否则沿用 greeter 的系统字体。时间为 72px、400 Regular、等宽数字及 -0.5px 字距；日期为 18px、400。时间和日期仍为深色、无描边。没有新增字体文件或网络下载。
- 按实际字形左边缘对齐，而非只对齐文字框：通常共同左边缘 E=72px，时间字形顶边 71.75px、日期 152.25px。用携带相同字体、字重、数字特性和渲染方式的 TextMetrics 动态修正留白，避免写死某个数字的偏移。窄屏 E=max(24,floor(宽度×0.075))，列宽不超过 288px。
- 登录区通常从屏幕高度的约 45.1% 开始，底边保留安全距离。头像为 48px 绿色圆形、22px/500 白色首字母；用户名为 18px/500。密码宽 288px、高 42px、圆角 8，箭头直径 33px。密码及手动用户名输入框保留既有暖白 View 背景，现为不透明，输入文字 15px/400。
- 用户名和底部文字保留深色 alpha 0.85 的字形描边。错误文字保留原有红色 Negative 与白色 alpha 0.90 描边，14px/400；不采用设计参考中的新红色或白色错误字。错误行与密码间隔 8px，没有错误时不占高度；短暂错误边框、提交与失败清空密码、失败后聚焦均不变。
- 密码下操作行高 32px、间隔 10px：会话与只读键盘布局在左侧，关机与重启靠右，组间至少 12px。四项字高 14px，标签 400、值与按钮 500。只缩略会话值，标签、键盘布局和电源文字不缩小；会话列表显示完整名称。悬停为暖白 alpha 0.16，焦点由不透明的白线和深色外沿组成，常态无底色。控件框允许略悬出字形对齐线，文字仍对齐。
- 两个展开列表保留自身白色 alpha 0.90 背景、深色文字和绿色选中态。用户列表向下、会话列表向上，两者互斥；保留高度限制、滚动及焦点返回，不增加列表功能。
- Tab 顺序仍为头像行 → 密码 → 登录 → 会话 → 键盘 → 关机 → 重启，Shift+Tab 反向；单用户头像与键盘布局仅可聚焦，没有新动作。多用户保留“其他…”；空模型／未列出的记忆账号使用手动输入。隐藏或不可用项跳过，列表回车不穿透登录，Esc 返回触发项。
- 账号、会话索引、认证、无会话禁止提交、防重复、密码清空和电源能力判断均保留。版本、CLI、Home Manager 和锁屏不变。唯一新增模块选项是下面的可选本地字体路径。

描边继续使用 [QtQuick Text.Outline](https://doc.qt.io/qt-6.11/qml-qtquick-text.html#style-prop)，未引入额外 Qt 模块。[浏览器设计参考](design/sddm-v6-mockups/README.md)与下方实际 Qt／VM 证据分开保存，不将概念图当登录截图。

## 安装与启用

在系统 flake 中引用本地开发分支，并让 `inputs.kaltsit.inputs.nixpkgs.follows = "nixpkgs"`；将 inputs 通过 `specialArgs` 传给系统模块。尚未发布的源码请使用本地 `path`，不要把公开 1.3.0 当成本轮代码。

```nix
{ inputs, ... }: {
  imports = [ inputs.kaltsit.nixosModules.default ];
  programs.kaltsit-sddm.enable = true;
  # SDDM 服务须由你的系统配置自行启用；主题模块不会启用它。
}
```

将 `kaltsit-sddm` 加入现有 `nixpkgs.config.allowUnfreePredicate` 白名单，保留其他包的规则。独立包包含已有角色壁纸，因此不是全自由素材包；[原有署名](../CREDITS.md)及许可叙述保持不变。模块使用系统的 `pkgs.callPackage`，要求 Qt 6 的 SDDM。当前锁定依赖已包含 QtQuick、Controls.Basic、Layouts，不需要新增 `extraPackages`。

模块导入、或仅把包加入 `environment.systemPackages`，都不会启用主题。只有选项为 true 时设置主题名和安装资源，仍不会启用 SDDM 服务。
主题默认值优先级为 900：覆盖 Plasma 的 `mkDefault "breeze"`（1000），用户显式 `services.displayManager.sddm.theme = "…"`（100）优先。已有显式主题时，须自行移除旧值或明确选择 `KaltsitMedicalGreen`；模块不会强行覆盖。

### 可选本地字体

`programs.kaltsit-sddm.fontFile` 的类型是 `nullOr path`，默认 `null`。仅在主题启用且路径非空时，通过 `fonts.packages` 添加本地字体包；关闭主题或保留 `null` 时不添加字体，也不设置系统默认字体族。没有字体时 QML 仍可加载，不要求 OPPO Sans 才能登录。

```nix
programs.kaltsit-sddm = {
  enable = true;
  fontFile = /absolute/private/path/OPPO-Sans-4.0.ttf;
};
```

字体须自行取得并核对许可；项目不下载、公开分发或修改字体，也未根据交付材料中的二手报道核实授权结论。上例引用 flake 目录以外的绝对路径，未来求值／构建需要 `--impure`（例如 `nixos-rebuild build --impure --flake /path/to/system#host`）；不要为绕过此限制把字体提交到公开仓库。显式使用后文件会进入本地 Nix store 与所构建系统的字体集合，应避免把含该字体的产物上传公共缓存。本轮只构建字体包并在测试 VM 中加载，没有安装到宿主系统。

未来真机首次启用建议：保留已知可用的配置与上一代系统，先完成下面的 VM 验证，再在系统配置中加入上述选项，依次运行：

```sh
sudo nixos-rebuild build --flake /path/to/system#host
sudo nixos-rebuild boot --flake /path/to/system#host
# 在方便时重启，下次启动生效；首次不要用 switch。
```

这些是未来由操作者执行的说明。本轮只在独立测试环境中验证，没有部署主机配置，也没有运行主机 switch、boot、test 或重启登录服务。

## 关闭与恢复

将 `programs.kaltsit-sddm.enable = false`，恢复之前显式设置的主题（若有），再 build、boot，并在下次重启观察。若自行额外安装了主题包，可从原安装列表移除。关闭模块不自动改写用户其他 SDDM 设置。
界面无法使用时，从启动菜单选择上一代；或尝试 Ctrl+Alt+F3 登录 TTY，再执行 `sudo nixos-rebuild boot --rollback` 和 `sudo reboot`。命令来源、上一代保留要求及未验证的主机恢复边界见[设计中的恢复说明](SDDM-DESIGN.md#风险与恢复)。
SDDM 的内置回退只处理 QML 加载错误，不能保证显示服务器、插件或认证故障可恢复。本主题没有自动切换脚本。

## 可重复的隔离验证

先构建主题；用同一锁定 nixpkgs 的 `kdePackages.sddm` 和 `kdePackages.qtdeclarative` 提供测试工具。以下命令只用测试脚本创建的私有 HOME、XDG 目录、D-Bus 和 offscreen，不操作日常会话：

```sh
nix build --no-write-lock-file path:.#kaltsit-sddm
python3 tests/run-sddm-native.py "$(realpath result)" \
  --greeter /path/to/matching/sddm-greeter-qt6 \
  --qml /path/to/matching/qml --output /tmp/kaltsit-sddm-native-result
```

使用同一命令追加 `--font-file /absolute/private/path/OPPO-Sans-4.0.ttf`，在另一个 `--output` 目录测试有字体模式；脚本只把字体复制到私有测试 HOME，并使用独立 fontconfig 缓存。省略该参数测试系统字体回退。不要混用输出目录。

脚本先加载真实 greeter 的 `--test-mode --theme`，六秒后结束测试进程，再用同版本 `qmltestrunner` 和假 SDDM 模型发送实际按键、鼠标事件。每组运行 17 项行为检查，覆盖零／单／多用户、手动用户名、会话、Tab／回车／Esc、重复提交、密码清空、错误与电源调用；分别检查 1280×800／100%、1920×1080／100%、3120×2080／175% 布局。

输出根目录有 `results.json`；分辨率子目录包含单用户、错误、多用户列表、长用户名、会话列表、空用户模型、头像／键盘焦点及纯背景的原生 PNG，以及逐区域的 `contrast.json` 和字形边缘 `alignment.json`。这些是假模型的原生 Qt 渲染，不是认证证明。175% 时 Qt 抓图的逻辑尺寸取整使原始 PNG 为 3120×2081；报告分别记录请求布局、逻辑尺寸与实际截图尺寸，不裁切或缩放来掩盖差异。

VM 配置在 [tests/sddm-vm.nix](../tests/sddm-vm.nix)，**仅用于测试，不得导入物理机器配置**。使用 2 核 / 2048 MiB、1280×800、静态壁纸与 X11 greeter；用一个 xterm 会话隔离验证 SDDM，不把它当 Plasma 桌面验收。测试账号 `tester`，公开的一次性密码 `wallpaper-test`。没有主机 HOME 共享、真实密钥或主机配置导入；Nix store 使用只含测试闭包的独立只读镜像，禁用默认共享目录及外网访问。

在新的临时目录创建测试 flake（替换源码路径）：

```nix
{
  inputs.theme = { type = "path"; path = "/absolute/path/to/kaltsit-medical-green"; };
  inputs.nixpkgs.follows = "theme/nixpkgs";
  outputs = { theme, nixpkgs, ... }: {
    nixosConfigurations.sddm-test = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [ (theme + "/tests/sddm-vm.nix") ];
    };
  };
}
```

然后仅在该临时目录执行：

```sh
nixos-rebuild build-vm --flake path:.#sddm-test
./result/bin/run-sddm-test-vm
```

先试错误密码，再用测试密码登录；xterm 中执行 `exit` 返回 greeter。关机和重启按钮只在 VM 中检查。
损坏主题回退测试必须在 VM 内：复制主题到 VM 的临时目录，故意写入无效 Main.qml，并通过 VM 的 SDDM 临时配置指向它，再重启 **VM 内** 的 display-manager。检查 `Fallback to embedded theme` 与可用登录控件后移除 VM 临时覆盖。不要对主机照做。
